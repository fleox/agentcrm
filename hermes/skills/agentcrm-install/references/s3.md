# S3-compatible storage for AgentCRM

Use TWO buckets: a PRIVATE one for the data (journal backend) and a public one for the admin app. One access key can cover both.

## Access key (least privilege)

- **AWS**: IAM user with a policy on both buckets: `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` on `arn:aws:s3:::<bucket>/*` and `s3:ListBucket` on `arn:aws:s3:::<bucket>`. Store it: `! npx -y @fleox-agent-crm/agentcrm@0.11.0 credentials set s3:main`, or import a profile with `--from-aws-profile <name>`.
- **Cloudflare R2**: R2 → Manage API tokens → Object Read & Write, scoped to the buckets. Endpoint `https://<account-id>.r2.cloudflarestorage.com`, region `auto`.
- **OVHcloud**: Public Cloud → Object Storage → S3 users; endpoint `https://s3.<region>.io.cloud.ovh.net`. Set `publicRead: true` on the hosting bucket.
- **Scaleway**: endpoint `https://s3.<region>.scw.cloud`.

## CORS on the data bucket

The browser admin reads and writes the data bucket directly, so the bucket needs a CORS rule for the admin's origin. `doctor` prints the exact JSON; it looks like:

```json
[{ "AllowedOrigins": ["https://crm.acme.com"], "AllowedMethods": ["GET", "PUT", "DELETE", "HEAD"], "AllowedHeaders": ["authorization", "content-type", "cache-control", "x-amz-*"], "ExposeHeaders": ["ETag"], "MaxAgeSeconds": 3600 }]
```

AWS: bucket → Permissions → CORS. R2: bucket → Settings → CORS policy. With the aws CLI: `aws s3api put-bucket-cors --bucket <bucket> --cors-configuration file://cors.json` (wrap the array as `{"CORSRules": [...]}`).

## Hosting bucket

Enable static website hosting (index document `index.html`) or put a CDN in front (CloudFront, Cloudflare) with HTTPS. `siteUrl` in the plan is that public HTTPS URL; the admin is served at `<siteUrl>/admin/`.
